# 用户自主抽奖与大屏同步

日期：2026-11-16；状态：用户已确认并授权开发；本地实现与验证记录见 docs/maintenance/acceptance.md。

## 已确认需求
- 根据活动名单生成个人抽奖码。用户打开活动链接，输入抽奖码，在开放时间内随时自主抽奖。
- 用户页面显示自己的中奖结果；多人可以同时提交。
- 大屏分页展示多位中奖客户，包含姓名、门店、奖品，姓名和门店沿用现有中间文字打码规则。

## 方案与建议默认值
- 采用开放时间内自主抽奖、结果队列分页展示。逐轮主持人放行不符合本次已确认需求；只展示最新一人的方式会覆盖同时中奖结果，因此不采用。
- 管理端生成和导出姓名、门店、个人抽奖码，后续补生成不更换已有码；支持单人换码并使旧码失效。随机码不使用电话或顺序编号。
- 每场活动设置明确时区的开始、结束时间和暂停开关。服务器在活动锁内按开始时间包含、结束时间不包含校验。归档后不可抽奖。
- 抽奖码验证后建立仅限本活动、本人权限的短期会话；参与者无需管理员登录。仅能查询本人资格、本人结果和相关奖品图片，不开放名单或图片目录。输入验证、来源校验与限流覆盖公众接口。
- 沿用每人1或2次机会，与主持台共用剩余次数和库存；奖品沿用单人抽奖按剩余份数加权的规则，无空奖。暂停、次数耗尽或无库存时明确提示。
- 同一请求重试返回原结果；已提交成功的请求在关闭时间后仍可恢复结果。不同人的请求不能互相查询或复用。
- 抽奖、库存、资格、换码与配置修改遵守活动级数据库锁；随机结果由服务端保存后再播放动画。与正在进行的主持台开奖互斥并给出可重试提示。
- 自主抽奖大屏采用独立展示模式，建议每页12人（3列×4行），默认8秒翻页，支持暂停与手动翻页。展示姓名、门店、奖品名称和缩略图，长文本换行或截断。
- 服务端为结果提供稳定顺序；新结果按顺序加入后续页面，不打断当前页。未播放结果优先，队列播完循环历史；刷新可恢复浏览位置，已作废结果退出展示。大量积压时显示待展示人数。
- 打码复用现有算法：单字为*，两字保留首字，三字及以上中间最多两字替换为*；例如张三丰为张*丰。后台原始资料不变，大屏不含电话和抽奖码。本人页面仅显示本人的信息。

## 实现边界与验收
- 保留现有主持台及其8人分页；12人分页仅用于新的自主抽奖展示模式。
- 现有JSONB活动聚合在活动锁下串行更新。先复用一致性机制，使用虚构数据验证多人并发；未经实测不承诺具体并发容量，若不能满足现场规模，再评估拆表。
- 行为测试覆盖时间边界、暂停、归档、无库存、次数共享、换码、越权查询、并发不超发、幂等恢复和结果排序。浏览器验证手机输入、本人结果、大屏分页、长门店名称、打码和断网恢复。
- 验证命令：npm test、npm run typecheck、npm run build、npm run test:e2e。
- 当前为本地项目。外部手机访问需要可达的部署地址；真实PostgreSQL、HTTPS、备份恢复及现场并发容量未验证前明确标记待验证。
- 不提交真实名单、抽奖码导出、密码或数据目录；不加入内定、付费、公开报名或短信功能。

## 用户确认的交互修订
用户要求手机端像电脑端先开始滚动、再点击停止显示礼品。复用PrizeMachine礼品滚轴，手机三列，结果卡突出奖品。开始即锁内保存结果，停止仅揭晓；30秒自动揭晓，关闭、刷新或断网不重抽。本人历史及全部投屏接口在揭晓前隐藏该结果。

## 新中奖大屏展示修订

用户要求最近新中奖用户先放大停留2秒，再变小回到原12人排版。新增居中焦点卡，显示原有打码后的姓名、门店、奖品及图片；保留2秒后用320ms过渡缩回网格对应位置。多人按服务端结果顺序逐个排队；未完成放大展示前不先出现小卡片。焦点展示时暂停自动及手动翻页，完成后恢复原翻页设置。首次打开既有历史不逐个重播，后续新结果才进入队列；队列与已播状态独立保存，历史翻页不重新放大。减少动态效果设置下保留2秒，缩回改为淡出。
