## 方向与方案

保留联网事务后台，新增主持控制层和大屏场景层（推荐）。考虑过整体替换开源3D抽奖项目，因本地存储、Vue/React差异及业务字段迁移不采用；考虑过一次性复制互动平台全部游戏，因需要多种业务规则和公网参与系统，先拆成后续包。

本轮礼品动画：前置礼品池、真实图片/名称、三列滚动、依次减速停在服务端结果、原结果重播。单人动画按可抽礼品展示，批量动画只展示选中的礼品。暂无跨设备开始/停止的场景状态同步，不将现有结果轮询宣称为完整遥控系统。

## A. 下一批：抽奖现场完整包

不依赖微信账号或付费服务，在当前电脑本地/已部署后台即可验收。

| 模块 | 具体交付 | 核心约束 |
|---|---|---|
| 场景导航 | 欢迎、礼品墙、抽奖、中奖墙、结束页；主持人一键切换 | 配置和当前场景由服务端保存，刷新能恢复 |
| 双屏控制 | 控制台与纯展示窗；当前奖项、人数、参与者、连接状态 | 后端场景版本号与轮询/SSE；重连按版本恢复，避免旧事件重放 |
| 主持节奏 | 预览礼品、开始滚动、停止揭晓、下一轮、跳过/重播动画 | 开始请求生成并保存唯一正式结果；停止仅揭晓，不生成第二次结果；网络异常查询原请求 |
| 安全收尾 | 等待停止超过30秒自动完成揭晓；操作离开需提示 | 防止主持窗口关闭后大屏无限转动；已保存结果不能被丢弃 |
| 奖项轮次 | 特等奖/一二三等奖等可自命名，绑定礼品、每轮人数、排序、完成进度、追加特别奖 | 轮次安排不突破共享库存与每人中奖规则；修改已完成轮次不改历史 |
| 参与范围 | 全部名单、公司、门店、手工到场状态筛选；明确显示本轮可抽人数 | 默认仍为启用名单；筛选条件随请求保存并在活动锁内重验，不通过前端删名单控制概率 |
| 视觉玩法 | 礼品老虎机（本轮）、姓名卡滚动，后续可选3D卡片；礼品和结果布局适配 | 视觉风格与随机算法分离；超大名单按显示层限制渲染，不删业务奖池 |
| 庆祝与声音 | 开场3-2-1、滚动/停奖音、庆祝彩带、静音/音量、可上传有权使用的音乐 | 大屏需先点击开启声音并试听；不宣称远程指令能绕过浏览器播放限制 |
| 现场快捷操作 | 空格开始/停止、F全屏、M静音、R重播、翻页笔；收起工具栏 | 输入框、弹窗、请求未确认时不响应抽奖快捷键；长按不重复提交 |
| 独立彩排 | 同配置、同名单展示的彩排场景、醒目标记、随时重置 | 不写正式轮次、中奖记录、库存或领奖状态；不得把彩排截图当正式中奖 |
| 中奖展示 | 单人特写、多人大卡分页、中奖墙、同轮回看、导出中奖结果图 | 回看和导出不重新抽；大屏始终不显示电话 |
| 领取管理 | 待领取/已领取、领取时间、核销记录、撤销核销原因 | 核销幂等；作废中奖与撤销核销是不同操作，领取后作废须显式提示 |
| 现场自检 | 后台连接、礼品图片、声音试听、全屏、当前规则、名单/库存可用性 | 图片失败、断网、未试听均显示未通过/待确认，不能默认PASS |
| 恢复与维护 | 本轮请求恢复、断线状态、记录与图片联合备份、运行日志 | 保留已有幂等与审计；现场不自动安装或升级 |

### 状态和数据

现有活动聚合新增带默认值的 `stageConfig`、`stageSession`、`roundPlans`；人物新增 `checkedIn`，中奖新增领取状态与核销日志。旧数据缺少新字段时采用兼容默认：正式流程、全部启用名单、不改变重复中奖规则。

舞台状态：待机 → 准备本轮 → 滚动中（结果已保存但未揭晓）→ 减速 → 已揭晓 → 下一轮。客户端动画完成确认不能作为库存提交条件。大屏接口在正式揭晓前不返回待揭晓姓名/奖品快照；控制端可查询回执用于恢复。开始、停止、切场景、核销均带请求ID/期望版本，活动事务内处理。

一个活动同一时间一个正式轮次运行；其他管理员设备可查看，操作冲突明确提示。现场前端渲染不持有独立中奖算法。

### A包验收

实际双窗演练欢迎→礼品墙→单人抽奖→批量→回看→中奖墙→结束页；空格长按不多抽；拔网/超时恢复同一个结果；停止与自动揭晓不重复；彩排不改正式数据；核销重复请求只记录一次；刷新能恢复场景与页码；声音在真实投影电脑人工确认；一千/一万人名单下分别检查计算正确性和显示层性能，不能用自动测试代替现场帧率。
