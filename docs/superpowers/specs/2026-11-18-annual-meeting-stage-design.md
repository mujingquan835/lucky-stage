# 年会主持模式设计

日期：2026-11-18。已确认同轮包含指定和随机名额，大屏对两种来源采用同一揭晓效果。

## 目标与方案

活动筹备时批量给名单绑定照片，现场使用人物滚动揭晓。投影电脑打开现有现场大屏，主持人用专用手机页面控制活动。用户选择同轮混合抽奖，指定与随机名额共用一份轮次结果。

- 照片可按姓名自动匹配或按 Excel 映射。以模板中的「照片文件名」为主，唯一姓名匹配作为快捷方式。文件名映射支持相机原文件名和同名员工。
- 指定获奖可以使用单独颁奖轮次，也可以与随机名额混合。采用用户选定的混合方案，开抽时一起核对资格与库存。
- 手机可以直接打开现有桌面工作台，也可以走独立主持页面。建议使用独立页面，复用现有后台登录、舞台状态和操作接口。

## 名单照片

- 名单模板增加可选「照片文件名」列。已导入的名单提供单独的照片匹配入口，允许多选照片及上传包含姓名、电话、照片文件名的映射表。照片补传只更新照片，不再次导入抽奖机会。
- 明确文件名映射优先。按姓名匹配只处理唯一姓名且未配置文件名的参与者。重名、重复文件名、同一人对应多张、未知参与者和无法读取的图片显示在预览中。支持手动指定、替换和移除。确认前预览缩略图与匹配结果，未解决项目可留待下次处理，结束后提供成功、失败与缺图明细。
- 上传复用现有的 JPEG、PNG、WebP 内容校验和大小限制，按批次限并发处理，单张失败可重试。服务端生成适用于滚动的 WebP 图，保存到持久存储，照片读取需管理员登录。安装迁移兼容无照片的活动，备份和恢复包含已绑定照片及仍在历史中奖快照中引用的照片。
- 活动级舞台选项允许批量抽奖使用人物滚动。大屏预载有上限的候选缩略图，动画可以循环播放。缺图或加载失败用姓名卡补位。中奖后使用中奖结果中的照片和姓名快照；多人沿用大屏分页，重播以原结果揭晓。

## 同轮指定与随机名额

- 仅在主持台批量轮次设置指定名单。暂定输入本轮总人数，再添加指定人；随机人数自动计算为总人数减指定人数。混合轮次至少保留一个随机名额，零指定名额沿用现有随机流程。总人数仍以 50 为上限。
- 建议首版保存每场活动的一份下一轮草稿，支持会前准备、换设备继续和现场调整。保存草稿不预留库存与资格，成功开抽后清除已使用草稿。草稿共用舞台版本校验。
- 指定礼品轮次共用本轮礼品。礼品池轮次逐名选定指定人所获礼品，随机名额按现有礼品池规则分配剩余库存。两部分共用库存和单批上限。
- 开始时在活动锁内重新核对所有指定人属于当前筛选范围、启用且有剩余机会、同一人只出现一次。先计算指定奖品所需份数，再从排除指定人的合格池无放回随机抽取余下名额。任一部分无法满足时整轮拒绝，不扣库存、不消耗机会。
- 一次事务写入同一个轮次。指定配置参与幂等校验，按原请求恢复同一结果。桌面与手机显式确认本轮总人数及指定、随机名额。后台中奖明细、导出与操作日志记录指定或随机来源。大屏统一滚动、统一揭晓，以服务端确定的混合展示顺序显示姓名、照片和礼品，展示接口始终省略配置及来源字段。滚动阶段只下发候选和轮次状态。历史数据兼容既有记录，自主抽奖维持原规则。
- 大屏舞台接口返回筛选后的展示字段。指定配置只由授权的主持端提交和读取，既有普通抽奖接口不接受指定参数。
- 停止只控制揭晓，沿用现有自动揭晓。已产生结果的纠正沿用带原因的作废流程。

## 手机主持台

- 每场活动生成专用入口和二维码。手机打开先验证现有管理员会话，登录后回到该活动。二维码只包含入口地址。手机与投影设备需要能访问同一个部署地址。
- 手机首页显示本轮状态、当前大屏页面和开抽／停止操作。支持单人、批量和混合配置，添加礼品时支持填写名称、库存并拍照或选图。可切换欢迎、礼品墙、抽奖、中奖墙、结束及翻页。审核、归档等管理功能沿用现有后台。
- 手机与电脑共用活动锁、舞台版本与请求标识。舞台版本冲突时刷新当前状态并提示重新确认。网络中断时保留原请求，恢复后查询结果。礼品提交失败重试应避免创建两份礼品，并尊重开奖期间的现有库存修改限制。

## 验收

- 用虚构照片验证原文件名批量匹配、同名冲突、缺图、错误文件、补传、替换、移除、历史照片快照、访问控制和备份恢复。
- 验证混合轮次不重复选人，指定和随机合计人数正确，两部分共用库存和上限，资格变化会拒绝整轮，同一请求重试以及双设备并发只生成一次结果。覆盖普通轮次、自主抽奖和旧数据。
- 双浏览器分别模拟手机和大屏，验证登录返回、添加礼品、切屏、人物滚动、停止揭晓、断线恢复。运行 npm test、npm run typecheck、npm run build、npm run test:e2e。部署前另验目标 PostgreSQL、HTTPS 和备份恢复。
